# Diagnostic probes

## Ordered texture batches

`node scripts/instrumentation/fused-outline-composite.mjs --probe=batch --output=/tmp/tilefun-ordered-texture-batches`
compares one-texture submission with four/eight textures through the production
GPU surface. Eighteen full RGBA pairs cover mixed raw/sRGB textures, translucent
overlap, nested union clips, 4,101-quads/capacity, source uploads, page seams,
transforms, reset/recovery and a shader-limit change. Every channel must match;
the capacity case must use three batches and three reused sources one batch.
The car probe also checks queued-image eviction and disable/drain lifetimes.

`city-audit.mjs --batch-textures=1 --defer-cached-images=false` keeps the new
layout but selects diagnostic one-texture/immediate car submission. Four/eight
samplers use `--batch-textures=4|8 --defer-cached-images=true`. For a strict
pre-change comparison, save the old `GpuRasterSurface.ts` first and add
`--raster-reference=PATH` to the one-texture/immediate control. The report hashes
the actually substituted source; the private path is not published. It changes
only that production module and retains the same current Worker/scene sources.

`--render-profile=true` includes a separate desktop quad/texture-switch census
and hypothetical one/two/four/eight-texture batches, keeping all hard barriers.
These counters add overhead and do not establish phone timing. Native timing
runs without attribution or validation and retains thermal aborts separately.
The pixel host also accepts `--cdp=URL --port=PORT` after creating owned USB
forward/reverse routes. It opens/closes only its own page on the native context,
uses `noDefaults` to avoid emulation, and disconnects without closing user Chrome.
Fixed 512px canvas readback qualifies the device shader; it is not an FPS sample.
[180](../../docs/tactical/180-ordered-texture-batches.md) owns decisions/evidence.

## Native city workload

`node scripts/instrumentation/city-audit.mjs --arrival=core --overview-zoom=0.05 --seconds=8 --warm-seconds=4 --output=/tmp/tilefun-city-audit`
profiles standing, walking, driving, warmed overview and zoom entry in a fresh
seed-2026 city through the real game, dedicated Worker, IndexedDB and GPU renderer.
Use `--stages=standing,drive,overview-drive,zoom-entry` to select/order stages;
repeated stage names are allowed. `--arrival=gateway` uses the existing city-center
inspection; `core` uses the same plan's central north/south extent. Overview zooms
are 0.05/0.1/0.25. Default GPU/mesh mode still has sprite fallbacks for native models.
`--renderer=canvas` or `--meshes=false` changes the renderer control explicitly.

Use `--arrival=racetrack` for the south spectator entrance,
`racetrack-north` for the north spectators, or `racetrack-center` for the infield.
`--viewport=1440x900` selects a desktop viewport (the default remains 411×789).
`--parked-fleet=true --arrival=racetrack-center --stages=overview --overview-zoom=0.25`
adds the first 45 registered road models through native parked placement in an
track-centered grid. Placement must succeed for every model; the report retains
the actual list. Some placements obstruct racers; use this for rendering density,
not an unchanged-race simulation comparison or a saved-depot reproduction.
Compare `--meshes=false` and the existing `--mesh-target-reuse=true` intervention
separately. The latter changes diagnostic target retention only;
it is not a production optimization or a pixel-parity acceptance result.

Native driving setup stops and boards an existing horizontal-route car. Record its
actual model, lane and pose: load/spawn timing can select different neighborhoods
and populations, so these are workload profiles, not matched before/after controls.
`--drive-model=compact-1` replaces that one car through the production factory to
exercise actual authored GLB draws without increasing the car count; it is an
explicit fixture variant. Subsequent motion uses native input. Travel and actual
mesh draw counters distinguish blocked/unused-model runs. Captures retain timings,
counts, server/frame timelines, input acknowledgement delay and correction error.
The client sampler also records player position about once per second (`motion`),
so a long driving capture can distinguish moving intervals from a blocked tail;
`maxTravel` alone is maximum displacement, not continuous-motion evidence.
`--drive-reverse-at=20` switches the held horizontal direction after about 20
sample seconds using the same touch/keyboard input. It is an explicit out-and-back
fixture variant, useful when a straight long drive eventually blocks. It does not
teleport or reset the vehicle; check `motion` and `inputChanges` for actual travel.
`--deep=true` adds indexed authority driving candidate counts when available,
per-query/traffic counters and per-car/per-tick distinct terrain
cells; `--cpu=true` samples only the owned Worker and main page at 1ms. Run these
attribution lanes separately from shallow timings; inclusive phases overlap.

Physical CDP uses `--cdp=URL --port=PORT --android-device-cli=PATH` and defaults to
native touch joystick input (`--touch=false` selects keyboard). The default entry
and post-setup gate is <=32°C/status zero; `--cooldown-seconds=60` is bounded.
A changed end thermal status retains that capture and stops subsequent cases.
Use machine-control's Android guide for owned USB routes, preserve original routes
and foreground state, then remove only task-owned routes. If cooldown uses the
launcher, explicitly launch Chrome again before attaching: Android may freeze a
background browser even while its forwarded debugging socket still exists.
The runner closes its
own tabs/Workers/server and clears only its isolated origin; it disconnects CDP
without closing the user's Chrome. Task-local private/raw reports remain outside
Git. `--root=PATH --revision=LABEL` profiles a frozen Git archive; source/probe hashes
are recorded alongside the supplied revision label.

[124](../../docs/tactical/124-city-workload-profile.md) records the initial captures,
thermal-stopped phone coverage, scene selection differences and next proposals.
Callback cadence does not measure displayed GPU presentation; these profiles do
not reproduce the original desync or establish crowded-city capacity.

## Collision broad-phase scaling

Run `node --import tsx scripts/instrumentation/collision-broad-phase.mjs
--output=/tmp/tilefun-collision-broad-phase` for three repeats of 0/24/96/384
resting/traveling native dogs through production Realm/ScenarioSession. It uses

Worker game controls. [115](../../docs/tactical/115-collision-broad-phase.md) owns

## Rotated vehicle collision demand

`npm run vehicle-collision:bench -- --output=/tmp/tilefun-vehicle-collision`
compares diagnostic cardinal AABB and yaw OBB bodies through the native entity
SpatialHash. It runs 64 prescribed motion steps against sparse/dense obstacles,
nearby cars and two rotating roof occupant clearance probes. Counts default to
1/8/32/128; 128 exceeds the current gameplay traffic cap and is a stress case.
Use `--counts=1,32 --samples=12` for a smaller selection. Authority-shaped work
checks all cars in a dedicated Worker; the main-thread lane checks one controlled
car six times per step while refreshing nearby proxies once. This models replay
demand, not the production PlayerPredictor or an actual Realm tick.

Both policies use identical motion, occupant positions and sweep subdivisions;
collision verdicts do not change routes. The AABB control uses nearest-cardinal
56x20 dimensions, not the complete approved per-view vehicle bank or facing
hysteresis. The OBB uses a diagnostic four-axis SAT test plus vertical intervals.
The native index uses enclosing XY boxes. Every probe counts all nearby candidates
and tests all overlapping candidates (no early exit). Static obstacles are entity
proxies, not the production prop index. Indexing/geometry/probe counts and checksums
are retained. Independent polygon and brute-force tests protect the prototype.

Run timing probes sequentially without competing tests/profilers. Three warmup
traces precede adaptive calibration; both policies use the same cycles until the
faster reaches 25ms (up to 1,024 traces). Twelve measured pairs alternate A/B then
B/A. Reported percentiles are batch-amortized milliseconds per trace step, not
server tick p95. Raw batch durations, timer precision, idle display cadence,
source hashes and hardware context make limits visible. No timing threshold is
asserted. Display calibration does not normalize CPU/GPU hardware capacity.

Use `--cdp="$PHONE_CDP_URL" --port="$PHONE_HTTP_PORT" --device="model / OS"`
for the physical phone after Machine Control discovery and task-owned ADB routes.
`--android-device-cli="$ANDROID_DEVICE_CLI"` records temperature/thermal status.
The runner closes its Worker/tab, disconnects from CDP and closes its Vite server;
it writes no browser storage and leaves the user's phone Chrome running. Restore
the prior foreground app and remove only task-owned USB routes afterward.
With no CDP endpoint it uses bundled full Chromium, reaped on completion.

The fixture has no gameplay consumer and measures no solver, AI, actual prediction,
networking, streaming, rendering, mesh geometry or full-game headroom. Discrete
4px sweep sampling includes rotation-only motion but is not CCD; oversized motion
fails rather than silently reducing samples. [096](../../docs/tactical/096-rotated-vehicle-collision-benchmark.md)
owns device results and the next shared-engine integration slice.
